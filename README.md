# Pokédex

A Pokédex that looks and feels like it runs on a Game Boy Color. The whole UI lives on the LCD of a Berry-red shell sitting on a dark desk, and the D-pad, A, B, START and SELECT are real buttons the app binds to navigation. Pokémon data comes from [PokeAPI](https://pokeapi.co/) over GraphQL.

This is a portfolio project. It started life as a Next.js app and is being rewritten in SvelteKit, one phase at a time. What is on this branch right now is phase 1: the SvelteKit skeleton, the typed GraphQL client, the design system, and the Game Boy shell as the root layout. The Pokémon screens, auth, database and deploy are phases 2 to 5 and have not landed yet, so if you run it today you get a working device with a placeholder screen.

## Stack

- SvelteKit 2.70 on Svelte 5.57 (runes only)
- Vite 8.3
- TypeScript
- Plain CSS. No Tailwind, no CSS-in-JS, no component library.
- GraphQL against PokeAPI, with types generated by graphql-codegen
- Vitest and Testing Library for tests, Biome for lint and format

## Getting started

You need Node 22 and pnpm. The `packageManager` field in `package.json` pins pnpm 11.22.0, so if Corepack is enabled you get the right version for free. Do not use npm here.

```sh
pnpm install
pnpm dev
```

Vite prints the local URL when it starts, usually `http://localhost:5173`.

## Scripts

| Script | What it does |
| --- | --- |
| `pnpm dev` | Start the Vite dev server |
| `pnpm test` | Run the Vitest suite once |
| `pnpm run lint` | Biome check (lint and format, read-only) |
| `pnpm run check` | `svelte-kit sync` then `svelte-check` against `tsconfig.json` |
| `pnpm run build` | Production build via the Netlify adapter |

`pnpm run codegen` regenerates the GraphQL client from the live PokeAPI schema. You only need it when the queries in `src/lib/pokemon/queries.ts` change.

## Design system

The production CSS lives in `src/lib/styles/`, split into tokens, base, type, components and the device shell, with `index.css` pulling them together. It is signed-off design output. Treat it as read-only unless you are the design owner.

`docs/design/style-guide.html` is the visual reference for that CSS, and `docs/design/README.md` explains the research behind it (the RGB555 palette, the two pixel grids, why the LCD is gray-green and not white). Open the style guide over HTTP, not from `file://`. It pulls fonts from Google Fonts and sprites from PokeAPI, and browsers block those requests from a file URL.

```sh
cd docs/design && python3 -m http.server 8000
```

Then visit `http://localhost:8000/style-guide.html`.

## Deployment

The target is Netlify. `netlify.toml` sets the build command and pins Node 22 and pnpm 11, and `@sveltejs/adapter-netlify` produces the output. There is no deploy automation on purpose: the free plan has a small monthly credit budget and a production deploy eats a chunk of it, so deploys are done by hand.
